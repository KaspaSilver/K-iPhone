**Result:**
- No Critical or High bugs.
- Ten Medium. Three are in today's work and could cost money:
  - Swap's deposit screen can pay the deposit twice.
  - Kasshi's sheetless sign-in signs any text, not only Kasshi's challenge.
  - A Kasshi payment whose answer was lost is reported as declined, inviting a second payment.
- The worst battery bug is in Buy Kaspa with Debit Card: two poll loops can end up waking each other
  with no wait.
- The most visible problem is language: every Received KAS notification and every in-app Posts
  banner is built in English, whatever language K is set to.
- Several of today's own changes need a second pass:
  - expired-username warnings can show the previous account's names;
  - clearing a Cold Storage account's name keeps its first letter;
  - the one-time bell migration misfires for new accounts.

## Medium

**M1. Swap's "Send KAS from K" can pay the deposit twice. ✔**
- Where: `SwapView.swift:1632-1653` (`SwapDepositScreen`).
- What's wrong:
  - The button shows whenever Kaspa goes in, whatever the swap's status.
  - It opens `WithdrawKaspaView` without `onSent`, so the swap never records `kasSendTxId`.
- Scenario: send, see Sent, tap Done. The same screen still offers "Send KAS from K" until ChangeNOW
  sees the deposit, about a minute on the 10 s poll. A second tap sends the full amount again, and
  getting it back depends on ChangeNOW's refund.
- Fix: pass `onSent`, store the txid on the swap, and replace the button with "Sent: <txid>". Also
  hide the button once the status is past new/waiting.

**M2. Kasshi's sign-in-first auto-signs any message, from any kasshi.io page or subdomain, for 120 s. ✔**
- Where: `KaChatSiteWallet.swift` (`signInApproved`, `preConnect`, the `signMessage` branch,
  `close()`).
- What's wrong:
  - The approval checks only the site key (which covers `*.kasshi.io`) and the time.
  - It never checks that the text is Kasshi's sign-in challenge.
  - It survives navigation, and `close()` doesn't clear it.
- Scenario: a compromised script or a user-content subdomain sends another Kaspa site's login
  challenge. The signature is KasWare's personal-message scheme and isn't bound to an origin, so it
  works wherever that scheme logs people in.
- Fix:
  - Auto-sign only text in Kasshi's challenge shape: it names `kasshi.io` and the connected address,
    with a nonce or recent timestamp, and is short.
  - Allow `kasshi.io` / `www.kasshi.io` only.
  - Clear the approval on the first main-frame navigation after load, and in `close()`.
  - Show the Sign sheet for anything else.

**M3. A Kasshi payment with an unknown outcome is answered "rejected" (4001). ✔**
- Where: `WithdrawKaspaView.send` (`ContactsView.swift` ~1934-1990), `SiteWalletSheets.swift:25-34`,
  `KaChatSiteWallet.decline`.
- What's wrong:
  - `NodePoolService.confirmAfterLostAnswer` throws `SendOutcomeUnknownError(txId:)`.
  - The view calls `onSent` only on success, and closing the sheet runs `decline()`.
  - The provider's `4002` "may have been sent" and its `txid` field are never used.
- Scenario: a pay-per-view payment's answer is lost. Kasshi shows it declined and the person pays
  again.
- Fix:
  - Finish the request with 4002 and the txid on `SendOutcomeUnknownError`.
  - Have `errorAnswer` carry `txid`.
  - Hold further `sendKaspa` calls for a few minutes, as `TrestlyTrade` does.

**M4. Buy Kaspa with Debit Card: two poll loops can ping-pong with no wait. ✔**
- Where: `CardBuy.swift` `CardBuyTracker.clear` / `ensurePolling` / `run` / `wait`.
- What's wrong:
  - `clear()` cancels loop A while it is parked in `wait()`'s continuation, and cancelling doesn't
    wake it.
  - A new loop B's first `wait()` calls `pollSoon()`, which resumes A. A exits, and its
    `defer { loop = nil }` clears the slot B now holds.
  - The next `ensurePolling` starts loop C. From then on B and C wake each other in turn.
- Cost: `/buy-api/order` back to back for each network round trip. Offline, it becomes a busy spin
  on the main actor. It lasts until the order finishes.
- Same code:
  - A paid order stuck in `signAgain`, `bridging` or `paid` never expires, so it polls on every beat
    forever.
  - The loop also survives Log Out.
- Fix:
  - Give each loop its own token, and clear `loop` only if it is still this loop.
  - Give each run its own continuation, resumed on cancel.
  - Cancel the sleeper when it's cut short.
  - Add an age cap for paid orders.
  - Call `clear()` on sign-out.

**M5. Expired-username warnings can belong to the previous account (two reviewers).**
- Where: `KachatExpiredNamesModel.load` (`KachatNamesLiveViews.swift` ~3890), read by `AppTabBadge`,
  `YourDomainsCard` and the Wallet banner.
- What's wrong:
  - The model has been an app-wide singleton since today, and nothing clears `expired` or `dismissed`
    on Log Out or an account switch.
  - `load()` captures `me`, awaits, then assigns without re-checking the account.
  - A failed read keeps the old list.
- Scenario: account A has a name in grace; switch to B. B shows A's red Wallet dot, A's "1 Expired"
  and A's banner, and a tap opens A's name. `dismissAll()` then writes A's keys into B's store. If B's
  read fails, this stays.
- Also: the model looks only at the chatting key. A name held on a spending address (an older Buy
  From) gets the red pill in the list, but no dot, count or banner.
- Fix:
  - Remember which wallet the list is for, and reset it when `$currentWallet` changes.
  - Re-check `myKey` after each await.
  - Build the list from `ownNamesAndOffers(heldOnly: true)`.

**M6. Cold Storage account rename: clearing the name leaves its first letter. ✔**
- Where: `ColdStorageView.swift` (`ColdStorageAccountCard`: each `draft` change calls
  `renameAccount`); `ColdStorageManager.renameAccount` ignores an empty name.
- What's wrong: backspacing "Cold Storage 1" to empty leaves the account named "C". Every partial name
  is saved along the way.
- Also: each keystroke re-encodes all accounts, and the label is part of `refreshColdCaches`'
  fingerprint, so the cold-address derive task restarts on every keystroke.
- Fix:
  - Keep the draft local and save on Done or focus loss.
  - Put the old name back if the field is empty.
  - Take the label out of the fingerprint.

**M7. A refunded debit-card order says "Open to bridge it again", but opening it starts a new
purchase. ✔**
- Where: `BuyKaspaViews.swift:11-26` (`DebitCardBuy.open`); `isFinished` includes `.refunded`.
- What's wrong: `open` clears the order and opens a new page. The refunded USDC sits in the derived
  Ethereum wallet, with no way back to it in K.
- Fix: open a `.refunded` order on its page, like `.signAgain`, or change the wording.

**M8. The Profile bell: room history floods it with old mentions and pushes out newer rows. ✔**
- Where: `PublicChatService.insertRoomMessages` (~1203); `GlobalNotificationCenter.record` (~148).
- What's wrong:
  - Every newly stored room message that @'s you becomes a bell row, whatever its age.
  - Groups skip history from before the group was created on the phone; rooms have no such guard.
  - `record` inserts at the front and keeps `prefix(100)`: the 100 rows added most recently, not the
    newest.
- Scenario: join #kaspa. Its 30 days load, every past mention becomes a row (all unread on a new
  install), and yesterday's Received KAS rows fall out.
- Fix:
  - Sort by time before trimming.
  - Skip mention rows older than the room's join time (or a few days) when they arrive by backfill.

**M9. A username receipt's "View in Explorer" opens a blank page. ✔**
- Where: `KachatNamesLiveViews.swift:578,630,683`.
- What's wrong: with K Explorer as the default since today, `txURL` is `kachat://explorer-tx/…`,
  which is handed to `InAppBrowserScreen`. Its navigation policy cancels it.
- Fix: open K Explorer links through `ExplorerDeepLink`, and use the browser only for http(s).

**M10. Received KAS notifications and in-app Posts banners are English in every language. ✔**
- Where:
  - `AddressActivityNotifier.swift:510, 548, 581, 586, 592`: "Received … KAS", "Balance
    increased…", "N of your addresses", "Chatting address…", "Spending address…". Only the Cold
    Storage line is localized.
  - `KaPostsAPIClient.swift:1884-1899`: "liked your post", "replied to your post", "followed you",
    "tipped your post: …".
- These are among the most seen texts in the app. Older than this week, but not in earlier audits.
- Fix: route them through `AppLocalization.string` with format keys, in all 19 languages.

## Low

**Money and signing**
- L1. The Kasshi sign-in sheet and a site request can collide (`ContactsView.swift` ~2412-2440):
  - If the page calls `requestAccounts` while "Sign In to Kasshi" is up, its `ask` never finishes.
  - Every later request then answers -32002, and the auto-sign check fails.
  - `try? preConnect` swallows errors, so K says you signed in when nothing connected.
  - Fix: in `preConnect`, answer a pending connect with the picked address.
- L2. The card-buy permit amount isn't tied to the order (`CardBuy.swift:355`): up to $1M is accepted.
  For someone who imported their MetaMask words, that is MetaMask's account 0 holding real USDC. Cap
  the amount at the order's amount plus a margin (beside the open spender item).
- L3. A kUSDT swap's history entry can land on another account if accounts switch during `execute`
  (`TrestlyTrade.recordSwap` / `SwapService.recordKusdtSwap`). Capture the account first, as the
  ChangeNOW path does.
- L4. Unchecked UInt64 addition of third-party amounts can crash:
  - Explorer: `ExplorerAPI.swift:305, 435`, `ExplorerModels.swift:158`, and the K-stats counts;
  - Swap: `SwapView.swift:431` converts a ChangeNOW Double to UInt64 without a clamp.
  - Fix: use `&+` or a saturating add, cap at max supply, and use `clampedUInt64`.

**Privacy and input**
- L5. Explorer search sends any 64-hex text to kaspa.stream 350 ms after typing stops
  (`ExplorerViews.swift:394-418`). A pasted private key would leak. Look up 64-hex only on Return,
  and refuse if it matches one of this wallet's keys.
- L6. Any app can close K's open sheets with a `kachat://explorer-…` link (`ExplorerDeepLink.open`
  dismisses everything). That includes a Send review mid-send, the backup steps, or a Kasshi send
  (which then answers 4001). Dismiss only for links tapped inside K, or queue the route.
- L7. Room delete records sit in one 2,000-entry list. A flood of fake deletes can push out real ones,
  so deleted messages come back where a source still serves them. Record non-held deletes only for
  txid-shaped targets, capped per sender.

**Notifications**
- L8. The one-time bell migration (`KachatNamesRegistry.swift` ~2077) misfires in two ways:
  - Its flag is set only when an earlier snapshot exists, so a new account's second check announces
    stale renewal and grace notices.
  - It's set before the posts, so an account switch mid-check loses those rows.
  - Fix: set the flag when `old == nil` too, and only after a complete check.
- L9. `pushCoversChatting` reads `isRegistered`, which is false for a while after every update and
  switch. Local reminders then duplicate pushes until the next refresh. Re-run the notifier when
  `isRegistered` changes, or decide from push mode.
- L10. A deleted room message keeps its bell row and its lock-screen notification. On a delete, remove
  `mention-<txid>` and the delivered notification with that id.
- L11. The app icon count drifts: room and KaPost pushes increment the shared count even for an APNs
  retry, and for a push the app hid. Skip it when `pushSeenBefore`, and force `applyIconCount` on
  backgrounding.
- L12. An empty `/broadcast-channels` answer is taken as the full list, so two hours later every
  joined indexer room is left (pins, bells, history). Ignore empty or mostly-empty answers, and reset
  the listed-rooms record when the indexer URL changes.
- L13. A mention push for a room you haven't joined rings but never reaches the bell. Record a bell
  row from the push when it's shown or tapped.

**Screens**
- L14. kUSDT rename:
  - The placeholder is off by one ("Address #4" on the card "Address #5").
  - A saved name starting with "Address #" is treated as the default and can be wiped.
  - Fix: use `addressNumber(forIndex:)` and read the stored label.
- L15. Kaspa Hub remembers its section across sign-out and account switch (`HubRouter` is never
  reset). A section left without `noteLeft` is never forgotten. Reset it on sign-out, and treat
  `leftAt == nil` off the Hub tab as "left now".
- L16. A Cold Storage card's balance counts hidden addresses, but the account's Total Balance doesn't.
  Use one rule (count everything, as Manage Addresses does).
- L17. Kasshi keeps running behind another tab until Kaspa Hub is tapped again (it isn't kept alive,
  but nothing closes it). Close non-kept sections when the Hub tab is left.

**Battery**
- L18. SwapDepositScreen keeps polling every 10 s on failed, refunded or expired, and re-saves the
  whole history each time even when nothing changed. Stop on any end state, and save only on a change.
- L19. Expired-names loads run two or three at once at launch and on every `didBecomeActive` (Control
  Center, the shade). Keep one in-flight load, and skip unless the revision changed or a minute has
  passed.
- L20. In-place rename saves and redraws on every keystroke:
  - kUSDT: `tokens.objectWillChange.send()` redraws every TokenWallet observer.
  - Manage Addresses and Cold Storage: a UserDefaults decode and encode each time.
  - Fix: save on Done (with M6).
- L21. Cold Storage's account screen reloads fully, including about one `/names/by-owner` request per
  address, on every own-address UTXO change. Debounce it, and refresh name tags only on appear or
  pull.
- L22. `HubTabInterceptor` keeps the last session's view closures after sign-out. Small memory only.
