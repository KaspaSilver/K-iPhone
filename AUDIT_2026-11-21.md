# K audit, 2026-11-21

**Code:** commit 278de352 (everything since the last audit at d7c56280: the all-in-one port of KaPay,
KaPost and KaPlay, and the K rebrand, about 106,000 lines), plus the uncommitted dock avatar.
**Method:** read-only. Five reviewers covered security and money, untrusted input and privacy,
smoothness and battery, bugs and crashes, and dead code. Items marked ✔ I re-checked in the code
myself.
**Not covered:** App Store review items, by standing request. Nothing in AUDIT_2026-11-20.md that is
fixed or "left as is" is repeated.

**Result:**
- No Critical or High security issues. No way found to lose funds. The new money paths (Trestly
  bridge, Cold Storage send, .kachat market) are carefully built.
- The worst problems are in how the three apps were joined:
  - account data that doesn't follow Log Out or Delete Account;
  - a block stream that runs all the time on Wi-Fi;
  - Kaspa Hub sections that reload every time you open them.
- About 3,700 lines of dead code came in with the port, plus 33 unused strings that still name
  KaPay, KaPost and KaPlay.

**Status, 2026-11-22: everything fixed in code, not yet built.** Partial or different from the
suggested fix:
- #6: Trestly's pinned code still uses public nodes; the approval sheet now says so.
- #19: indexer answers are size-capped and sanity-checked, but not signature-checked (the indexer
  sends no signatures for rooms; KaPost signatures are a follow-up).
- #22: look-alike letters in room names are not handled.
- #32: the Profile root no longer observes the wallet or drafts; a full split is left.
- #35: no batched replies endpoint exists, so row probes wait 0.6 s on screen instead.
- Dead code: the cold-storage history screen, the two fitted-sheet modifiers, the voice recorders
  and the REST helpers are not duplicates after all and stay; protobuf code untouched. The .kachat
  claim sheet and the expired-names banner were attached, not deleted.

## 1. Security and money

| # | Sev | Finding | Where |
|---|-----|---------|-------|
| 1 ✔ | Medium | **A Trestly trade can go through but be shown as failed.** A trade that runs past 240 s (or whose hidden page dies) throws "gave no answer" with no "check the address's history" hint. ## Held up well
- **Trestly bridge:**
  - origin, port and main-frame checks;
  - allow-listed methods, size-limited params, one trade at a time;
  - params captured before approval, worse quotes shown again;
  - non-persistent store, pinned pool code, network-blocked builder.
- **Cold Storage send:** never touches keys; the signed transaction is checked output by output and input by input, SIGHASH_ALL only.
- **.kachat market:** pinned templates; buy pays exactly the live price; names confirmed on chain for sends.
- **Keys, auth and logs:**
  - seed and key screens behind Face ID;
  - sensitive copies `localOnly` with expiry;
  - no secrets logged, no http.
- **Deep links and share:** links only pre-fill; only http(s)/mailto open from content.
- **Remote content:**
  - remote images capped and downsampled;
  - KaPost chain data and room chain scans verify signatures and authors;
  - chess input bounded and checked;
  - link previews only for named posters on allow-listed hosts.
- **Performance already done right:**
  - KaPost cells are Equatable;
  - polls stop in the background;
  - no timer or observer leaks in the new code.
