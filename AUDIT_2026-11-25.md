**Method:** read-only, six reviewers:

5. the Explorer;
6. today's chat, room, notification and Nextcloud changes.

Items marked ✔ I re-checked in the code myself. Anything earlier audits list as fixed or "left as is" isn't repeated, and owner decisions aren't findings.

**Result:**
- No Critical issues.
- Battery: one problem outweighs everything else. **K never tells the node to stop sending blocks**, so after the Explorer, a group scan, a room without an indexer or an indexer blip, the node keeps pushing every full block (about 10 a second) for the rest of the connection. That can be hours on stable Wi-Fi.
- Next biggest:
  - the Explorer's animated block graph keeps drawing after you leave it for other Hub screens;
  - nothing in the node pool pauses in the background;
  - about ten unaligned timers stop the cellular radio from ever going idle while K is open.
- Correctness: today's work has no High bugs. The worst are:
  - my own "unaccepted" filter can drop a real Received KAS;
  - the old #kachat-bugs name still opens the dead room;
  - the Explorer freezes on a wss node and shows wrong amounts in two places;
  - the Nextcloud folder move can race.

**Status, 2026-11-25: everything fixed in code, built, not yet committed.** B15 (owner: "do it like
X"): with push registered the KaPost poll is a 5-minute safety net; the push asks for a poll, and
K polls on opening and when Profile shows. Without push it runs on the shared beat. Checked on the simulator: launch subscribes, the 15 s keepalive runs on
Wi-Fi, and leaving the Explorer logs "Stopped block-added notifications". Other partial or
different fixes:
- B4: one shared wall-clock beat (`ForegroundBeat`) for the room sweep, KaPost, kUSDT and the
  group pass, instead of a merged loop.
- B9: the preload's decoded file isn't kept for the first Play (up to ~32 MB per bubble); Play
  decodes once off the main thread and a finished one-part note keeps its file.
- B18: the indexer's payment push carries no payload, so the tip check is still a (light, 4 s)
  fetch; an indexer flag for tips would remove it.
- B19c: ChatService's resubscribe retry stands down while the pool's own is retrying, rather than
  being removed (it still covers a failure before the pool takes the subscribe).
- E4: payloads stay on address pages (the API can drop them entirely but not send a prefix, and
  the kind needs one); pages are 20, then 40.
- C1: the chatting address's floor is held below a skipped coinbase under 10 minutes old.
- Not yet tested against live servers: the Nextcloud folder move (C7), wss header decoding (C3),

Q1 was tested by reassembling KasSigner's own `sweep.reply.abandon12`, split by a Swift port of
`write_split`:
- in order, reversed, with duplicates and noise;
- a tag change, a forged digest, a single framed code, another format, a bare KSPT, and v1.0.7 sets.

The result decodes as a signed 0x06 reply. Not tested with a real unit. Done differently from the
suggestion:
- **Q3:** the change address is reserved for the session at build and marked used only once
  broadcast, so an abandoned send doesn't use up a hand-scanned address.

  pool's coins are in.

- **M2:** Request Payment's Fresh Address is a quantum address, so it isn't watched for kUSDT. A
  regular address picked there is.
- **Q7:** the testnet prefix point is still unverified.
- **M10:** needs nothing until the indexer sends a payload.

**Result:**
- **One Critical:** a quantum cold send can't be finished. Nothing goes out wrong; it just dead-ends.
